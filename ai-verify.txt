# 1. Biggest issue: `Soft Delete` for Product Manager

Your VS Code version says:

```text
Catalog | Soft Delete | ADMIN | PROD_MGR | ALLOW
```

I would **change this**.

Your previous matrix intentionally restricted Product Manager from deleting products, categories, brands and prebuilts. 

### Recommended

```text
Catalog | Archive/Deactivate | ADMIN | PRODUCT_MANAGER | ALLOW
Catalog | Soft Delete        | ADMIN | PRODUCT_MANAGER | DENY
Catalog | Hard Delete        | SUPER_ADMIN | DENY | DENY
```

But there's an important distinction:

### Better terminology

Don't call everything "delete."

Use:

```text
Publish
Unpublish
Activate
Deactivate
Archive
Soft Delete
Hard Delete
```

For example:

```text
Product Manager:
    Publish       ALLOW
    Unpublish     ALLOW
    Activate      ALLOW
    Deactivate    ALLOW
    Archive       ALLOW
    Soft Delete   DENY
    Hard Delete   DENY
```

If your application doesn't actually implement an archive system, don't invent an `Archive` permission either.

# 14. Your RBAC should not be only Role → Allow/Deny

This is the most important architectural point.

Don't implement your backend like:

```js
if (user.role === "ADMIN") {
   ...
}
```

Instead:

```text
User
 ↓
Role
 ↓
Permission
 ↓
Resource
 ↓
Action
 ↓
Scope
 ↓
Business Policy
```

For example:

```text
ORDER_MANAGER
    ↓
orders.refund
    ↓
Global
    ↓
Is order refundable?
    ↓
Is payment captured?
    ↓
Is refund amount valid?
    ↓
ALLOW
```

Your previous authorization flow already established exactly this model.
